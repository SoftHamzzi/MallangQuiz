---
description: 블로그에 복사해 풀어 놓은 말랑 퀴즈 문제지를 채점하고 해답 파일을 생성합니다.
---

블로그 폴더에 복사해서 직접 풀어 놓은 말랑 퀴즈 문제지를 채점하고, 같은 폴더에 해답 파일을 생성하세요.

**인자:** `$ARGUMENTS` — 문제지 파일명 또는 경로 (예: `2026-08-19-260819_mallang_quiz.md`)

인자가 비어 있으면 진행하지 말고 파일명을 물어보세요.

**⚠️ 문제지 파일(`*_quiz.md`)은 읽기 전용입니다.** 채점 결과·점수·피드백을 문제지에 절대 쓰지 마세요. 이 명령이 수정하는 파일은 오직 새로 만드는 해답 파일(`*_answer.md`) 하나뿐이며, 문제지와 **같은 폴더**에 생성합니다.

## 1단계: 파일 매칭

Bash 도구로 아래 명령을 실행하고 JSON 출력을 저장하세요:

```bash
node scripts/prepare-grade.js "$ARGUMENTS"
```

출력 JSON 구조:
- `quizPath`: 채점할 문제지 절대 경로
- `answerPath`: 생성할 해답 파일 절대 경로 (`_quiz.md` → `_answer.md`)
- `answerExists`: 해답 파일이 이미 있는지 여부
- `postDate`, `quizTitle`, `answerTitle`: 날짜와 제목
- `answerFrontmatter`: 문제지 frontmatter의 title만 해답용으로 바꾼 블록 (**그대로 사용**)
- `preamble`: frontmatter 다음에 오는 블로그 안내 문구 (**그대로 사용**)
- `questions[]`: `{ number, difficulty, source, sourceAbsolutePath, sourceExists, wrongNoteId, answerLabel, userAnswer, unanswered }`
  - `wrongNoteId`: 오답노트에서 나온(변형 재출제된) 문제면 `wn-xxxxxxxx` 형태의 ID, 아니면 `null`
- `matchedOutput`: 대응하는 원본 해답지 `{ folder, answersPath, quizPath, orderedMatches, exact }` (못 찾으면 `null`)
- `warnings[]`: 확인이 필요한 사항

스크립트가 실패하면 중단하고 이유를 알려주세요.

`warnings` 처리:
- `answerExists`가 `true`면 **덮어쓰기 전에 사용자에게 확인**을 받으세요.
- `matchedOutput`이 `null`이면 원본 해답지 없이 출처 문서만으로 채점한다고 알린 뒤 진행하세요.
- `sourceExists`가 `false`인 문제는 원본 해답지에만 의존해 채점하고, 해당 문제 피드백에 그 사실을 적으세요.

## 2단계: 자료 읽기

아래를 모두 Read 도구로 읽으세요 (동시에 읽어도 됩니다):

1. `quizPath` — 문제지 전문 (사용자 답안 포함)
2. `matchedOutput.answersPath` — 원본 해답지 (**정답의 기준**)
3. 각 `questions[].sourceAbsolutePath` — 출처 문서 (**채점 근거 보강용**)

또한 Glob 도구로 `quiz-templates/*.md`를 가져와 Read 하세요. 각 문제가 어떤 템플릿(객관식 / OX / 빈칸 채우기 / 서술형)으로 만들어졌는지 판별하는 데 사용합니다.

**중요:** `questions[].userAnswer`는 `📝 내 풀이/선택/답` 표기 뒤쪽만 잘라낸 것입니다. 사용자가 문제 중간(예: 소문항 (1) 바로 아래)에 답을 적어 둔 경우도 있으므로, **문제지 전문을 읽고 해당 문제 블록에서 사용자가 추가한 모든 서술을 답안으로 취급**하세요. 원본 문제 문장과 사용자가 덧붙인 문장을 구분해서 판단하세요.

## 3단계: 채점

문제마다 **10점 만점**으로 채점합니다.

**유형별 배점**
- **객관식**: 정답 10점 / 오답 0점
- **OX**: 판단(O/X) 7점 + 근거 서술 3점. 근거를 안 적었으면 근거 점수만 감점하세요.
- **빈칸 채우기**: 빈칸 개수로 10점을 균등 배분 (예: 빈칸 3개면 각 3.33점, 소수 첫째 자리까지 반올림)
- **서술형**: 원본 해답지의 핵심 논점을 2~4개로 나누고 균등 배분해 부분 점수를 주세요.

**판정 기호**
- `⭕ 정답` — 만점
- `🔺 부분 정답` — 0점 초과 만점 미만
- `❌ 오답` — 0점이지만 답을 시도함
- `⬜ 미응답` — 답을 쓰지 않음

**미응답 판정**: `unanswered`가 `true`이거나, 템플릿 플레이스홀더가 그대로 남아 있거나, "기억이 나지 않는다" / "모르겠다" 같이 **명시적으로 포기한 서술**이면 미응답(0점)입니다.

**채점 원칙**
- 정답의 기준은 **원본 해답지**입니다. 출처 문서는 사용자의 답이 해답지와 표현만 다른지, 정말 틀렸는지 판단할 때 근거로 쓰세요.
- 표현이 달라도 **핵심 개념이 맞으면 정답** 처리하세요. 반대로 결론만 맞고 근거가 틀렸으면 부분 점수를 주세요.
- 사용자가 물음표로 끝맺는 등 자신 없어 해도, 내용이 맞으면 점수를 깎지 마세요. 대신 피드백에 확신을 갖도록 근거를 짚어 주세요.
- 채점은 **후하지도 박하지도 않게**, 왜 그 점수인지 피드백에서 설명할 수 있는 수준으로 하세요.

**총점 계산**: `획득 합계 / (문제 수 × 10) × 100` → 소수 첫째 자리에서 반올림한 정수(백분율)

**등급**
| 백분율 | 등급 |
| --- | --- |
| 90~100 | 🏆 훌륭해요 |
| 70~89 | ✅ 잘했어요 |
| 50~69 | 🟡 복습이 필요해요 |
| 0~49 | 🔴 다시 공부해요 |

## 4단계: 해답 파일 작성

Write 도구로 `answerPath`에 아래 형식으로 작성하세요.

```markdown
{answerFrontmatter}

{preamble}

# 말랑말랑 퀴즈 — 해답지 ✅

**날짜:** {postDate}
**문제 수:** {N}문제
**총점:** {획득}/{만점} ({백분율}점) {등급}

## 📊 채점 결과

| 문항 | 유형 | 난이도 | 결과 | 점수 |
| --- | --- | --- | --- | --- |
| Q1 | 객관식 | 🟡 보통 | ⭕ 정답 | 10 / 10 |
| ... | ... | ... | ... | ... |
| **합계** | | | | **{획득} / {만점}** |

### 총평

{2~4문장. 잘한 부분과 약한 부분을 구체적으로.}

---

{각 문제 블록}
```

각 문제 블록은 **해당 문제가 쓴 템플릿의 "해답지 형식"을 그대로 따르되**, 아래 두 가지를 추가합니다.

1. 제목 줄에 채점 결과를 덧붙입니다: `## Q{번호}. {난이도} — {판정기호} {획득}/10`
   - `questions[].wrongNoteId`가 있는 문제는 오답노트 배지도 함께 유지하세요: `## Q{번호}. {난이도} · 📌 오답노트 — {판정기호} {획득}/10`, 그리고 문제지에 있던 `> **오답노트:** \`{id}\` · ...` 줄을 `> **출처:**` 줄 아래에 그대로 옮겨 적으세요.
2. `**정답:**` **바로 앞**에 사용자의 답안을 인용하고, 해설 뒤에 피드백을 붙입니다.

객관식 예시:

```markdown
## Q1. 🟡 보통 — ⭕ 10/10

**문제:** {문제내용}

- A. {보기A}
- B. {보기B}
- C. {보기C}
- D. {보기D}

**📝 내 답:** {사용자 답안}

**정답: {정답번호}**

**해설:**

{해설}

**🔍 피드백:** {왜 이 점수인지, 무엇이 맞고 무엇이 빠졌는지}

> **출처:** `{출처}`

---
```

- 문제 본문·보기·정답·해설은 원본 해답지 내용을 기준으로 하되, 출처 문서를 읽고 보완할 내용이 있으면 다듬어도 됩니다.
- 코드 블록·표·이미지는 원본 해답지 그대로 유지하세요.
- 미응답 문제는 `**📝 내 답:** _(미응답)_` 으로 적고, 피드백에 **꼭 기억해야 할 핵심**을 요약해 주세요.

마지막에 복습 섹션을 붙이세요 (만점이 아닌 문제가 하나라도 있을 때):

```markdown
## 📌 복습 포인트

- **Q{번호} {주제}** — {무엇을 다시 봐야 하는지 한 줄} → `{출처}`
```

## 5단계: 오답노트 갱신

4단계에서 매긴 판정을 바탕으로 오답노트(`.quiz-wrongnote/wrongnotes.json`)를 갱신하세요. 이 단계는 채점 결과를 저장소에 반영만 하는 기계적 작업이므로, 판단(누구를 오답노트에 넣을지)은 이미 4단계에서 끝난 상태입니다.

1. 문항별로 아래 필드를 담은 배열을 구성하세요.

   ```json
   {
     "wrongNoteId": "1단계 questions[].wrongNoteId 그대로 (없으면 생략)",
     "source": "questions[].source",
     "template": "2단계에서 판별한 템플릿 파일명 (예: fill-in-the-blank)",
     "difficulty": "questions[].difficulty",
     "concept": "이 문제가 정확히 무엇을 테스트하는지 한 줄 요약",
     "questionText": "문제 본문(질문 문장)만 — 보기/코드 블록 제외",
     "score": "이번에 매긴 점수(숫자)",
     "judgment": "⭕ / 🔺 / ❌ / ⬜ 중 하나"
   }
   ```

   - `concept`은 **`wrongNoteId`가 없고 판정이 `⭕`가 아닌(=신규 오답으로 등록될) 문제에만** 채우세요. 그 외에는 생략해도 됩니다.
   - `wrongNoteId`가 있는 문제(오답노트에서 변형 재출제된 문제)는 이번 판정이 `⭕`든 아니든 반드시 배열에 포함하세요 — stage 전이가 여기서 일어납니다.

2. Write 도구로 이 배열을 `.quiz-wrongnote/tmp-record.json`에 저장하세요.
3. Bash 도구로 아래 명령을 실행하세요.

   ```bash
   node scripts/wrongnote.js record --input .quiz-wrongnote/tmp-record.json
   ```

4. 출력 JSON(`{ added, advanced, reset, mastered, ignored, totalItems }`)을 확인한 뒤, 임시 파일을 삭제하세요.

   ```bash
   rm .quiz-wrongnote/tmp-record.json
   ```

스크립트가 실패해도 이미 작성된 해답 파일(`*_answer.md`)은 그대로 유효합니다 — 오답노트 갱신 실패를 이유로 해답 파일을 지우거나 재작성하지 마세요. 실패 사유만 사용자에게 알리세요.

## 6단계: 보고

생성한 파일 경로와 함께 **총점 / 등급 / 문항별 결과 한 줄 요약**, 그리고 **오답노트 갱신 요약**(신규/단계상승/리셋/마스터 개수)을 알려주세요.
